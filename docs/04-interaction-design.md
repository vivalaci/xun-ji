# 阶段四：交互设计

## 交互原则

| 原则 | 体现 |
|------|------|
| 无仪式感 | 没有「开始训练」/「结束训练」的状态切换 |
| 零强制节奏 | 训练和身体数据想记就记，无需主动打开记录模式 |
| 历史即默认 | 上次数据自动预填，降低输入量 |
| 数据即首页 | 打开就是曲线，不是欢迎语或今日摘要 |

---

## 核心流程一：记录训练

**目标**：5 个动作 × 4 组，3 分钟内完成。

```
训练 Tab（列表页）
  │
  ▼  tap "+"
  │
新建训练页
  ├─ 日期：自动填今天（可修改）
  ├─ 选择模板：[ 推日 ] [ 拉日 ] [ 腿日 ] [ 空白 ]   ← 关键改动
  │     ↓ 选「推日」
  │   载入推日模板的动作清单，并自动预填
  │   「上一次推日」每个动作的重量/次数（可修改）
  │
  ├─ 动作1：卧推
  │    组1  [-]  100 kg  [+]  ×  [-]  5 次  [+]
  │    组2  [-]  100 kg  [+]  ×  [-]  5 次  [+]
  │    组3  [-]  102.5   [+]  ×  [-]  4 次  [+]
  │    组4  [-]  102.5   [+]  ×  [-]  4 次  [+]
  │    [ + 加一组 ]
  │
  ├─ 动作2-5：同上
  ├─ [ + 添加动作 ]（从动作库选或自建）
  └─ [ 保存 ]  →  训练列表（新记录置顶）
```

> **复用逻辑（修正 #1）**：不再"复用上一次训练"，而是按模板"复用上一次**同类**训练"。
> 今天练腿选「腿日」，预填的是上次腿日的数据，而非昨天的推日。这是为了适配进阶训练者的分化训练。

**时间预估（按模板复用场景）**

| 操作 | 耗时 |
|------|------|
| 选择模板（1 次点击，自动载入动作 + 上次数据） | 5 秒 |
| 调整变化的组（约 5 组） | 30 秒 |
| 确认不变的组（约 15 组） | 45 秒 |
| 保存 | 5 秒 |
| **合计** | **~90 秒** |

### 重量输入控件（方案 C：混合）

- **点击数字** → 弹出数字键盘，直接输入任意值
- **点击 [-] / [+]** → 步进 ±2.5 kg（次数步进 ±1）
- 无上次记录时，字段为空，不预填

## 核心流程二：记录身体数据

```
身体 Tab（列表页）
  │
  ▼  tap "+"
  │
新建身体数据页
  ├─ 日期：今天（可改）
  ├─ 体重      [ ___ ] kg
  ├─ 体脂率    [ ___ ] %
  └─ 肌肉含量  [ ___ ] kg

  [ 保存 ]  →  返回列表（新记录置顶）
```

- 三个字段全部**选填**，填哪个算哪个
- 不强制记录周期，用户想记就记

## 核心流程三：查看进步曲线

```
曲线 Tab（首页）
  │
  ├─ 时间范围切换：[ 1M ] [ 3M ] [ 6M ] [ ALL ]  ← 默认 3M
  │
  ├─ 卧推最大重量  ────────────────╱───
  ├─ 深蹲最大重量  ──────────╱─────────
  ├─ 硬拉最大重量  ────────────────╱───
  ├─ 体重趋势      ──╲──────────╲──────
  └─ 体脂趋势      ──╲──────────╲──────

  点击任意曲线  →  动作详情页（放大图 + 完整历史列表）
  点击任意数据点  →  显示具体数值 tooltip
```

## 关键决策记录

| 决策 | 选择 | 原因 |
|------|------|------|
| 重量调整控件 | 键盘 + 步进混合（方案 C） | 兼顾精确输入和快速微调 |
| 记录模式 | 随时可填，无需主动开启（模式 C） | 不强制用户节奏 |
| 组数预填 | 用上次数据预填，可修改（方案 A） | 最大化减少重复输入 |
| 曲线默认时间范围 | 3 个月 | 足够看到阶段性进步趋势 |
| **#1 分化复用** | **训练模板**（预设推/拉/腿 3 套，名称+内容可编辑、可增删） | 按模板复用同类训练，避免预填错动作 |
| **#2 动作身份** | **动作库 + 稳定 id**（三大项内置核心、绑定曲线；其余可选/自建） | 曲线按 id 聚合，不靠字符串匹配 |
| **#3 曲线口径** | **主力工作组重量**（做组数最多的重量；并列取较重） | 反映真实训练重量，非最大重量/估算 1RM |
