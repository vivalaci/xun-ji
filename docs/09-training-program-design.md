> **动作引用**：下表所有 `id` 均来自现动作库 [config/exercises.js](../config/exercises.js)，已校验覆盖。
> **最后更新**：2026-06-15

## 一、循证要点（2019–2025 meta 分析与综述）

1. **容量为第一驱动力，边际递减**：每肌群**每周 ~10–20 个有效组**为黄金区间（MEV≈10、MAV≈12–20）；每多一组约 +0.24–0.38% 增长，越高越平，>~20 组多数人收益转负。
2. **频率本身不关键，价值在分摊容量**：容量相等时频率对增长影响很小；每肌群 **≥2 次/周**是为了把周容量拆开、每组质量更高、疲劳更可控——是手段不是目的。
3. **复合动作打头**：疲劳最低时先做多关节大重量动作（同类内复合在前、孤立在后）。
4. **次数区间**：力量 3–6 次 / 肥大主力 6–12 次 / 孤立泵感 12–20 次；全程留 **RIR 1–3**（≈力竭增长但疲劳更低）。
5. **组间歇**：大复合 2–3 分钟，孤立 60–90 秒。

**选型推论**
- **二分化（上/下，4 练/周）**：多数中级训练者最优，天然 2×/周、容量好分摊。
- **三分化 PPL**：**6 练**时最佳（2×/周）；**3 练**版每肌群仅 1×/周、单日容量被迫堆高，适合时间紧或进阶者。

## 四、与现状的差距 & 落地路径

- **现 `config/templates.js`**：5 套预设每套仅 5 个动作、且**无组次/RIR 信息**，与本设计有差距。
- **本设计涉及的所有动作 id 现库均已具备**——动作库覆盖度已足。
- **升级模板属模板数据口径改动**（且可能需新增「目标组次」字段，须可缺省 + 写迁移），按规矩在**另一会话**走 OpenSpec change，以本档为输入。
