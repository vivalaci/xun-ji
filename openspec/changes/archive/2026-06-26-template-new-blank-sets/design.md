## Context

`pages/workout/edit.js` 的 `buildFromTemplate` 在按模板新建时做历史值预填：

- 力量：找上一次同模板训练 `lastSame`，若该动作有 `prev.sets`，则把上次每组的 `weight/reps` 预填入新训练（渐进超负荷参考）；无历史才按 `targetSets` 铺空组。
- 有氧：把上次同模板的活动数据 `prev` 传入 `buildCardioItem`，预填 `duration/secondVal`。

副作用：用户未练、直接保存即把上次数据当今天存（见用户截图：上肢A 卧推预填 60×9/10/10/10）。用户期望按模板新建各组为空。

约束（CLAUDE.md）：保存口径「保留全部动作（未填补 0）」「完全空白拦截」既有不变；面向用户改动同步 `docs/usermanual.md` + `config/manual.js`（同源）。

## Goals / Non-Goals

**Goals:**
- 按模板（力量 + 有氧）新建时各组/活动初始为空，不预填上次数值。
- 保留 `targetSets` 组数布局与 `repLow/repHigh` 次数区间提示（循证目标，非历史数据）。
- 编辑既有记录的回显不受影响。

**Non-Goals:**
- 不改保存口径（保留全部动作、未填补 0、完全空白拦截）。
- 不引入"占位提示显示上次值"（用户明确要全空）。
- 不改模板结构与目标组次字段。

## Decisions

### D1：取消历史值预填，统一铺空组

`buildFromTemplate` 力量分支移除 `lastSame` 取值与 `prev.sets` 复用，统一走"按 `targetSets`（||1）铺空组（`{weight:'', reps:''}`）+ 区间提示"——即原"无历史"路径成为唯一路径。有氧分支不再查 `lastSame`，对每个活动 `buildCardioItem(te.exerciseId, null)`。清理因此不再使用的局部变量（如力量分支仅用于换算预填值的 `mainUnit`）。

- 否决"占位提示显示上次值、不计入保存"：用户明确要全空；占位实现要改输入组件 placeholder + 保存时区分"占位 vs 实填"，成本与复杂度更高。
- 渐进超负荷参考改由用户主动查看（动作详情曲线 / 历史列表 / PR）。

### D2：组数按 targetSets，不沿用上次组数

铺行数量用模板的 `targetSets`（缺省 1），不再用上次训练的组数。`targetSets` 是模板目标组数（预设来自 docs/09、自建来自存为模板时的组数），作为布局依据稳定且符合"按计划练"。

- 否决"沿用上次组数但留空"：徒增分支、用户只在意值为空。

### D3：依赖既有保存口径兜底

全空模板新建若用户未填任何一组，保存时既有「完全空白拦截」会提示填写、不落库——这正好根除"未练却存了数据"。填了部分则按「保留全部动作、未填补 0」存真实值。无需改保存逻辑。

## Risks / Trade-offs

- **[失去渐进超负荷快捷参考]** 不再自动带出上次重量 → 缓解：属用户主动选择；上次表现仍可在动作详情/历史查看；保留次数区间提示作目标锚点。
- **[老用户习惯变化]** → 缓解：用户手册（doc + in-app）同步改描述说明新行为。
- **[页面逻辑无纯函数单测]** `buildFromTemplate` 是页面方法 → 缓解：以模拟器/真机走查覆盖（选模板新建全空、未填保存被拦截、填部分正常存、编辑既有照常回显）。

## Migration Plan

无数据迁移。部署即页面 + 文档改动；回滚还原 `pages/workout/edit.js`、`docs/usermanual.md`、`config/manual.js`。
