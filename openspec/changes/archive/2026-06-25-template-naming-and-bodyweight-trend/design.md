## Context

迭代十一 `record-to-template`（已归档）的命名实现是 `utils/templateLib.js` 的纯函数 `recordToTemplatePayload`：

```js
name: ((record && record.name) || '训练') + '（我的）',
```

无条件追加「（我的）」，且归档需求明确"不去重"。叠加链：按「我的模板」新建训练时训练名继承模板名（`pickTemplate` 里 `name: tpl.name`），保存为模板再加一层后缀，反复操作得到「上肢A（我的）（我的）…」。同名记录多次保存还会撞出多条同名模板。

第二条（自重趋势）：曲线取点用 `util.dayLiftValue` → `util.mainWorkingWeight`，后者 `if (!w) return` 跳过 0 重量组，纯自重动作恒为 null，导致首页自定义曲线与 `pages/exercise/detail.js` 的曲线都无点（详情页只剩"纯自重，进步看次数"提示与历史列表，图为空）。

约束（CLAUDE.md）：命名/取值属纯函数逻辑，放 `utils/templateLib.js`、`utils/util.js` 并在 `tests/algo.test.js` 补例；图表只用 `utils/chart.js`；显示过 `unit.js`；写库走 `db.js`；不动集合既有字段。

## Goals / Non-Goals

**Goals:**
- 保存为模板时后缀幂等（最多一个「（我的）」）、不与现有模板重名；自动名仅作默认，用户可在保存时改名。
- 自重动作（`loadType==='bodyweight'`）在首页曲线与详情页按「当日最大次数」呈现趋势，不再为空。
- 命名与取值规则集中在纯函数、可单测。

**Non-Goals:**
- 不自动迁移存量已叠加的脏名（避免改动既有数据；用户可在模板编辑页自行改名）。
- 不改「我的模板」分组、置顶、order 末位等既有行为。
- 不改自重动作的录入与存储方式（仍按现状存 `weight`/`reps`），只改读取侧趋势取值。
- 不改 PR/容量等其它聚合口径（本次只动趋势曲线取值）。

## Decisions

### D1：基名归一——剥除尾部「（我的）」及其序号

把记录名末尾反复匹配并剥除 `（我的）` 可选跟随数字的片段，得到基名。正则示意（全角括号）：循环 `name = name.replace(/（我的）\d*$/u, '')`，直到不再变化；最终 `trim`，空则取「训练」。这样「上肢A（我的）」「上肢A（我的）（我的）」「上肢A（我的）2」「上肢A（我的）（我的）3」都归一为「上肢A」。

- 备选（否决）"只在末尾恰好等于一个（我的）时不追加"：处理不了带序号名（「上肢A（我的）2」会再叠加），且无法归一多层叠加，不彻底。

### D2：唯一化命名——重名追加最小序号

候选名 = 基名 + 「（我的）」。若候选名 ∈ 现有模板名集合，则尝试 候选 +「2」、+「3」…取第一个不在集合中的。首个不带序号（与现有「上肢A（我的）」一致的读感）。

- **比对范围**：与**全部模板**名比对（而非仅「我的模板」组），避免与任何预设/自建撞名造成列表困惑。
- 序号紧贴后缀（「上肢A（我的）2」），与 D1 的剥除正则对称，保证再保存能正确归一。
- 备选（否决）时间戳/随机串：可读性差，否决。

### D3：纯函数签名——传入现有名集合

`recordToTemplatePayload(record, existingNames)`：`existingNames` 为现有模板名数组（调用方 `pages/workout/edit.js` 的 `saveAsTemplate` 从 `db.getCache(TEMPLATES)` 取 `name` 列表传入）。函数内部完成 D1 归一 + D2 唯一化，返回含唯一 `name` 的 payload。`order` 末位仍由调用方补（依赖现有模板、保持原职责划分）。保持纯函数：不读全局、不写库，便于 `algo.test.js` 覆盖。

- 既有调用方若不传 `existingNames`（默认 `[]`）SHALL 退化为"加一个后缀、不编号"，向后兼容不报错。

### D4：保存时可编辑名称——`editable` 确认窗 + 默认名预填

`onSaveAsTemplate` 的 `wx.showModal` 加 `editable: true`，用 `content` 预填默认名（纯函数算出的归一+后缀+编号结果），`placeholderText` 提示"模板名称"。确定后取 `res.content`：`trim` 后非空则原样用作模板名，空则回退默认名。

- **用户输入不强制唯一/不加后缀**：与既有"模板编辑页重命名"行为一致（那里也不强制唯一），把命名主权交给用户；只有"默认名"才跑去重编号。否决"对用户输入也强制编号"：会篡改用户明确意图、与重命名页不一致。
- **改名两处入口**：保存时（本次新增 editable 窗）与事后（既有 `pages/template/edit` 名称输入框）。后者已实现，本次不动，仅在用户手册一并说明。
- 否决"在模板列表加内联重命名"：模板编辑页已能改名，再加入口冗余、超出本次范围。

### D5：自重动作趋势按最大次数取值

根因：`util.mainWorkingWeight` 跳过 0 重量组（`if (!w) return`），纯自重动作恒返回 null → `dayLiftValue` 为 null → 曲线无点。关键观察：**负重自重**（有额外负重的天）其实现在就能正常出重量曲线——真正为空的只有**纯自重**（全程 weight=0）。修法不动录入/存储，仅改**读取侧趋势取值**：

- `utils/util.js` 新增纯函数 `dayRepsValue(workout, ids)`：扫描当日匹配 `ids` 的动作各组，返回 `reps` 的最大值；无有效次数返回 null。与 `dayLiftValue` 对称，便于 `algo.test.js` 覆盖。
- **取值口径（按曲线整体判定，避免单位混用）**：仅当 `loadType === 'bodyweight'` **且**该曲线在当前范围内**没有任何一组带负重**（不存在 `weight > 0` 的匹配组）时，判为"纯自重"→ 用 `dayRepsValue` + 单位「次」+ **不过 `unit.toDisplay`**；否则（负重自重有负重，或 `weighted` 动作）→ 维持 `dayLiftValue` + kg。
- **为何整体判定而非逐日**：逐日会让同一条线一天 kg、一天「次」，单位混读无法标轴。整体判定保证一条线单位统一；负重自重里偶发的纯自重天按现状 `mainWorkingWeight` 返回 null、断线留空即可。
- **判定数据范围**：与画点同一份（当前 range 过滤后的 workouts）扫描是否存在 `weight > 0` 的匹配组；两遍处理（先判口径、再按口径取点）。range 切换可能改变判定，属可接受的少见情形。
- 显示侧：纯自重曲线 latest 显示「N 次」、单位标签「次」；详情页沿用既有 `isBodyweight` 与"纯自重，进步看次数"文案。注意 `isBodyweight` 仅据 `loadType`，详情页还需叠加"范围内无负重"才走次数，与首页口径一致。
- **为何用最大次数而非主力组次数/总次数**：用户明确要"训练组中的最大次数"；最大次数语义直观（最好一组）、单点稳定、与详情页历史一眼可对。否决"总次数"（受组数波动干扰）、"主力工作组次数"（纯自重无重量分组，口径不成立）。

## Risks / Trade-offs

- **[存量脏名不迁移]** 已有的「（我的）（我的）」模板不会自动修正 → 缓解：明确为非目标，用户可改名；新保存不再产生。
- **[与预设撞名编号]** 若基名恰为某预设名，唯一化会让「我的模板」出现「X（我的）」并在再撞时编号，属预期、不影响预设组 → 无需额外处理。
- **[缓存未就绪时 existingNames 不全]** 极端下缓存为空可能漏判重名 → 影响仅"偶发同名"，与原行为相比只会更好；可接受。
- **[同一动作既有负重又有纯自重历史]** 整体判定下，只要范围内有负重就整条按重量，纯自重那几天断线留空 → 缓解：符合"负重自重看重量"意图；空缺天与重量曲线既有断线行为一致。
- **[range 切换翻转口径]** 某 range 内全是纯自重→按次数，换到含负重的 range→翻成重量 → 缓解：少见且每个 range 内单位自洽；可接受。
- **[次数与重量单位混读]** 纯自重曲线单位「次」与重量曲线「kg」并存于首页（但各曲线内部单位统一）→ 缓解：各曲线卡片独立标注单位，latest 带「次」字样，不混淆。
