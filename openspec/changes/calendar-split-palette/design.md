## Context

日历配色目前在 `utils/calendar.js` 的 `TYPES` 定义，按**单日肌群**分 7 类（推/拉/蹲/上肢/下肢/有氧/其他），由 `classify(name)` 按训练名关键词归类，有氧按 `workout.type==='cardio'` 单独归。现有 7 色散在色轮上（蓝/青/紫/绿/玫红/橙/灰），无视觉分组。

而 `config/templates.js` 的 `group` 字段已把肌群严格嵌套进三个系统：

```
三分化 = { 推, 拉, 蹲 }    二分化 = { 上肢, 下肢 }    有氧 = { cardio }    其他 = { other }
```

系统可由现有肌群分类直接推导，**无需新增数据字段**。本次改动是纯展示层换色 + 图例重排。

约束：
- 不撞主题保留色：`--warning #F59E0B`（琥珀/腰围图）、`--danger #EF4444`、`--success #10B981`。
- 点很小，需高饱和、白底/卡片底可见。
- `classify`/`aggregateByDate`/`monthMatrix` 逻辑与签名不变，只换 `TYPES` 色值。

## Goals / Non-Goals

**Goals:**
- 日历上一眼可辨系统：一片蓝=三分化、一片绿=二分化、橙点=有氧。
- 族内仍能区分单日（推/拉/蹲、上肢/下肢）。
- 图例按系统分组，让"色=系统"的规则在图例里就立起来。

**Non-Goals:**
- 不改分类逻辑（仍按训练名关键词 + `type==='cardio'`）。
- 不加数据字段、不动 4 集合、不做存量迁移。
- 有氧不加形状区分（保持实心圆点，仅靠橙色，已与用户确认）。
- 不改日历网格、点击详情、折叠"+N"等已有行为。

## Decisions

### D1 配色原则：色相编码系统，族内色相弧 + 明度区分单日
色相族表达系统（用户主要诉求"一眼看系统"），族内用**加宽的色相弧 + 明度**区分具体那天。相邻的蓝族、绿族各自往**远离对方**的方向展开（蓝往紫端、绿往黄端），中间留最大空当保护族边界。

被否方案：
- **纯明度阶（同一蓝深→浅）**：族内聚最强但推/拉/蹲只靠深浅、最浅点白底偏弱、单日难认。用户选 A（色相弧）并要求族内"明显区分"，故否。
- **保留 7 散色另加角标/底色标系统**：信息冗余、点太小放不下角标，复杂度高。

### D2 色值表

| 系统 | 色族 | 单日 | 色值 | 相对现状 |
|---|---|---|---|---|
| 三分化 | 蓝族 | 推日 | `#4F46E5` 靛蓝 | 微调（原 `#1D4ED8`）|
| | | 拉日 | `#2563EB` 正蓝 | 微调（原 `#0891B2` 青）|
| | | 蹲日 | `#0EA5E9` 天蓝 | **换族**（原 `#7C3AED` 紫）|
| 二分化 | 绿族 | 上肢 | `#15803D` 深草绿 | 微调（原 `#059669`，挪离青端让路）|
| | | 下肢 | `#84CC16` 黄绿 | **换族**（原 `#DB2777` 玫红）|
| 有氧 | 橙 | 有氧 | `#EA580C` 橙 | 保留 |
| 其他 | 灰 | 其他 | `#9CA3AF` 灰 | 保留 |

两处真正的语义换色：**蹲日 紫→蓝族**、**下肢 玫红→绿族**——改完每个系统成一条连续色带。

### D3 图例按系统分组
图例从「一行平铺 7 色」改为「四组带小标题」：三分化(推/拉/蹲) / 二分化(上肢/下肢) / 有氧 / 其他。强化"色族=系统"心智模型，否则用户需自行归类，分组优势打折。色点与文案数据建议由 `calendar.js` 导出一份分组结构（或在页面侧静态映射），避免色值散落多处。

## Risks / Trade-offs

- **蹲日(天蓝 `#0EA5E9`) 与上肢(深草绿 `#15803D`) 是最近的跨族边界** → 已把上肢从原偏青的翠绿挪到偏黄的深草绿让路；若模拟器/真机仍觉接近，把蹲日往 `#2563EB` 收一档。最终肉眼微调。
- **绿(二分化)↔橙(有氧) 对红绿色盲可能发糊** → 用户已确认不加形状区分；有氧通常另有 cardio 摘要/标签辅助识别，接受此权衡。
- **测试若断言具体色值** → 同步更新 `tests/algo.test.js`；`classify`/聚合逻辑不变，分类相关用例不受影响。
- **色值散落风险** → 单一真源仍是 `utils/calendar.js` 的 `TYPES`；图例尽量复用同一来源，不在 wxml/wxss 里硬编码重复色值。
