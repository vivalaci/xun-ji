# Design: template-groups

## Context

模板现为平铺列表，预设 3 套（推日/拉日/腿日）由 `db.ensureTemplatesSeeded` 在云端集合为空时播种。模板已可被用户重命名、增删、改动作。存量用户（含开发者本人真机数据）的模板文档无 `group` 字段。架构铁律：不改 4 集合既有字段，新字段必须可缺省并写迁移方案；云读写只走 `utils/db.js`。

## Goals / Non-Goals

**Goals:**
- 模板获得分组语义（三分化/二分化/我的模板），选模板与管理页按组分节。
- 预设扩展为 5 套，"腿日"更名"蹲日"。
- 存量数据无感迁移，幂等且尊重用户后续删除。

**Non-Goals:**
- 不做用户自定义分组（创建/重命名/排序分组）——用户模板统一归"我的模板"。
- 不改训练记录（workouts）结构，`templateId` 快照语义不变。
- 不做模板在组间移动的 UI。

## Decisions

### D1：`group` 为模板文档上的可缺省字符串字段，而非独立集合
**选择**：在 `workout_templates` 文档加 `group: string`（缺省 = 我的模板）。
**被否方案**：新建 `template_groups` 集合存组实体。
**理由**：只有两个预设组且不开放自定义分组，独立集合是过度设计；字符串标签可缺省，完全符合铁律第 6 条，渲染时前端分桶即可。

### D2：迁移触发条件 = "存在缺 `group` 字段的模板"，不引入版本标记
**选择**：`ensureTemplatesSeeded` 拉到模板后，若有任一文档缺 `group`，执行迁移：名称 ∈ {推日,拉日,腿日} → `group:"三分化"`（腿日同时 `name:"蹲日"`）；其余缺失者写 `group:""`（显式空 = 我的模板）；迁移发生时一次性补种二分化两套。
**被否方案**：a) 本地 Storage 标记 seedVersion——跨设备不可靠（换设备会重复迁移）；b) 集合里放 meta 文档——污染数据集合且要改安全规则心智。
**理由**：迁移后所有文档都有 `group`（含显式空串），条件自然失效 → 幂等；用户之后删除二分化预设不会再触发补种（删除被尊重）。无需任何额外状态。

### D3：改名只精确匹配 `name === "腿日"`
用户已把"腿日"改成别的名字，说明有自己的命名习惯，迁移不动它（归"我的模板"）。代价：该用户拿不到"蹲日"自动改名，可自行改，可接受。

### D4：迁移写入走 `updateLocalFirst` / `saveLocalFirst`
与全 App 弱网策略一致：先改缓存即时生效，云端经队列重试同步。迁移在 `ensureTemplatesSeeded` 内完成后返回已迁移列表，调用方无感。

### D5：预设 order 全局递增（推0 拉1 蹲2 上肢3 下肢4），组内按 order 排
渲染时前端按 `group` 分桶（三分化 → 二分化 → 我的模板），桶内按 `order`。不为分组单独设排序字段。

### D6：二分化预设动作清单
- 上肢：bench、barbell_row、ohp、lat_pulldown、db_curl、tricep_pushdown
- 下肢：squat、rdl、leg_press、leg_curl、calf_raise
三大项覆盖：上肢含卧推、下肢含深蹲；硬拉留在三分化拉日（二分化用户可自行加入，模板可编辑）。

## Risks / Trade-offs

- [同名用户模板误归组] 用户自建过名为"推日"的模板（与预设重名且缺 group）→ 会被归入三分化。影响仅为展示分节，动作内容不被改动，可在模板编辑中接受；概率极低。
- [迁移期弱网] 迁移写入进队列未同步时换设备 → 另一设备重复迁移。操作均为幂等赋值（同值覆盖），最坏重复补种二分化 → 以"迁移事件发生时云端不存在同名+同组预设"做补种前检查兜底。
- [腿日历史训练显示] 训练记录存的是当时 `name` 快照，旧记录仍显示"腿日"——符合快照语义，不视为缺陷。

## Migration Plan

1. 发版后首次 `ensureTemplatesSeeded`：检测缺 `group` → 就地迁移 + 补种二分化（见 D2）。
2. 回滚：新字段可缺省，旧版本代码忽略 `group` 仍正常工作；无需数据回滚。
